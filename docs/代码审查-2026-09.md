## 一、总体评价

这是一个工程质量显著高于典型个人项目的代码库：

- **鉴权**：五种角色 token + 最长前缀匹配 + `compare_digest` 常时比较 + QQ HMAC-SHA256
  身份签名（300s 窗口、统一错误文案防 oracle），有"事故驱动"的注释留痕。
- **数据层**：WAL + 迁移单事务 fail-fast + `integrity_check` 双重校验；请求幂等层
  （`BEGIN IMMEDIATE` + 租约原子接管）跨进程安全。
- **测试**：server 830+ 用例覆盖鉴权矩阵/幂等/迁移/执行器安全；conftest 双层生产库
  护栏是真实事故后的机器强制。
- **前端**：零 CDN 依赖、统一 `apiFetch`、全 `textContent` 写入且有防 XSS 回归测试。
- **LLM 客户端**：SDK 重试关闭 + 应用层 Key 冷却指数退避 + 仅临时性错误切换 Key，
  避免"重复扣费式重试"。

以下问题均在上述高分背景下提出，按严重度排列。

## 四、审查过程中的事故记录（如实留痕）

1. **误触本地陈旧库**：做默认拒绝手工验证时，脚本未隔离 db_path，对本地
   `server/data/assistant.db` 跑了一次 `init_db()`。迁移事务按设计回滚（WAL 0 字节、
   主文件 mtime 未变），确认无写入。排查发现该文件是 9 月 1 日的陈旧开发遗留
   （10 条记忆、缺 schema_version 表），真库在部署服务器上。**教训**：任何手工脚本
   都应像测试套件一样先隔离 db_path。本地 `server/data/` 里的 t2.db / test_escape*.db
   建议清理（已被 gitignore，仅占磁盘）。
