## 一、C1 情绪周报（纯服务端，无 Windows 依赖）

**目标**：周报里加"本周情绪"一节——情绪分布 + 最常让你烦躁/疲惫的话题 + 情绪高峰时段。

**实现步骤**：

1. `server/app/services/mood.py` 新增：
   ```python
   def get_weekly_stats(days: int = 7) -> dict
   ```
   读 `mood_log` 近 N 天（东八区日期）记录，返回：
   - `total`：记录条数
   - `by_mood`：{情绪: 次数}（按次数降序）
   - `negative_topics`：负面情绪（烦躁/疲惫/低落）记录的 snippet 列表，按出现频率聚合
     top 5（v1 零 LLM：按 snippet 词频或直接按记录次数取 top；不做语义聚类）
   - `peak_hours`：情绪记录最多的小时段（如 "下午 15-17 点"）
2. `weekly_reflect.py` 的 `run_weekly_reflect()` 在组装周报 markdown 时追加一节：
   ```
   ## 本周情绪
   - 情绪记录 N 条：烦躁×a、疲惫×b、开心×c…
   - 情绪高峰：下午 15-17 点
   - 最常触发负面情绪的话题：1) xxx 2) xxx
   ```
   注入已有 stats dict 或正文皆可，风格对齐现有周报格式。
3. 测试（`server/tests/test_mood.py` 或新文件）：构造近 7 天 mood_log 数据 →
   断言 by_mood 计数、negative_topics top 排序、7 天外数据不计入。

**验收**：本地跑 `get_weekly_stats()` 单测过；JD 上线后周日 21:00 后 `/api/reports`
最新周报出现"本周情绪"节（可临时手动触发 `run_weekly_reflect` 验证，不必等周日）。

## 二、C2 小月表情反馈（桌面端，需离屏验证 + Windows 更新）

**目标**：用户连续负面情绪（B 档连击激活）或当天有负面情绪时，悬浮球进入"体贴模式"
（视觉变化），情绪转好自动恢复。

**实现步骤**：

1. **服务端加一个只读状态接口**（桌面端没有 mood.py，要走 HTTP）：
   - `server/app/api/chat.py` 或新文件：`GET /api/mood/state` → 返回
     `{"streak_active": bool, "today_text": str}`（内部调用
     `mood.get_streak_injection()` 是否非空 + `get_today_injection()`）。
   - 注意：只读、鉴权走全局中间件，不需要改桌面 token 逻辑。
2. **桌面端 `api_client.py`** 新增 `mood_state() -> dict | None`（GET /api/mood/state，
   timeout 8s，失败返回 None，参照 `due_reminders()` 的吞错风格）。
3. **托盘轮询**（照抄 `tray.py` 的提醒轮询模式）：
   - `_MoodWorker(QThread)` + 60s `QTimer`（情绪是慢变量，60s 足够）；
   - `streak_active=True` → `self.ball.set_state("caring")`；变 False → 恢复
     `set_state("online")`（若当时不是 thinking/error）。
   - 退出收尸沿用 `aboutToQuit → _shutdown()`（tray.py 已有，把新 worker 加进去）。
4. **悬浮球新状态 "caring"**：
   - `theme.py` 的 `state_colors()` 加 `"caring": <暖色>`（如暖橙 #f0a36b 一类，
     与现有四主题都协调；至少保证默认主题有值）。
   - `floating_ball.py`：`set_state("caring")` 后主色自动走 `_state_color()`；
     可选：`_tick` 动画里加"缓呼吸"节奏（caring 时呼吸周期拉长 1.5 倍）——
     简单加分项，不做也符合要求。
   - 三皮肤（bender/astro/classic）共用主色映射，不单独改绘制逻辑。
5. **离屏验证（必须做，UI 改动铁律）**：
   新建 `scripts/render_627_smoke.py`（参照 `scripts/render_626_smoke.py`）：
   - offscreen 起面板/悬浮球 → `ball.set_state("caring")` → 渲染 PNG；
   - 断言：主色像素含暖色（采样中心光晕/眼睛区域，颜色与 online 不同）；
   - 三皮肤各渲一张；全空白即失败。
6. **面板问候呼应（可选加分）**：`chat_panel.py` 打开面板时若 `mood_state()`
   返回 `today_text` 非空，问候语前加一句（如"今天状态一般的话，随时找我聊聊"）。
   改动小、效果好；不做不影响验收。

**验收**：离屏冒烟过；用户 Windows 拉取后（下方交接规矩第 6 条），对服务器连说两轮
负面情绪消息 → 60s 内悬浮球变色；发一句"哈哈搞定了" → 恢复。

## 三、交接规矩（接手者务必遵守）

1. **脱敏铁律**：仓库/文档不得出现任何真实姓名、手机号、邮箱、服务器公网 IP
   （含文档规则里的"示例"——示例一律用占位符，如 `user@example.com`、`x.x.x.x`）。
   真实值清单只存在于本地笔记/服务器 .env，从不进 git。推送前自查：
   扫描自己本次改动中是否有真实联系方式或公网地址。
2. **UI 改动先离屏验证**：`QT_QPA_PLATFORM=offscreen` 渲染 + 像素断言，通过才能交付。
3. **QThread 生命周期**：worker 用完必须 `retire()`（wait 后 deleteLater），
   否则 Windows 上会出 sizedFree 堆损坏崩溃（chat_workers.py 头注释有完整说明）。
4. **测试先写**：新逻辑进 `server/tests/`，`pytest -q` 全量绿才算完；修复必配回归测试。
5. **版本号**：服务端 `server/app/main.py` 的 `APP_VERSION` 递增（当前 0.2.4）；
   桌面面板标题 `desktop/chat_panel.py` 版本标记同步递增。
6. **Windows 更新流程**（用户执行）：`git pull` → 杀 pythonw 进程 → 起
   PAA-Collector 与 PAA-Robot-Supervisor 两个计划任务。**机器人/采集器是两个进程，
   改完代码两个都要重启**；面板标题版本号是更新成功的标志。
7. **git 工作流**：先 `git pull --rebase` 再 push；提交信息带课号（如"6.28 …"）。
8. **服务端部署**（JD，如无权限则只提交代码并写明）：pull → `pkill -f 'run\.py$'` →
   `cd server && setsid nohup .venv/bin/python run.py </dev/null >/tmp/assistant.log 2>&1 &`
   → `curl http://127.0.0.1:8000/api/health` 确认版本号。
9. 完成后更新 `docs/LEARNING_PROGRESS.md` 待办第 7 项与 `docs/LESSONS.md` 复盘。
