# 多人支持设计（v0.4）—— 小月 QQ 多用户

> 第 9 课。目标：任何 QQ 用户私聊小白（小月）都能聊，且按 QQ 号**完全隔离**
> 记忆；知识库/执行器/提醒等主人专属功能零暴露。本文档记录设计决策与运维要点。

## 一、三个核心决定（用户拍板）

| 决定 | 选择 | 含义 |
|---|---|---|
| 准入范围 | 任何陌生人都能聊 | 需要陌生人限流与防滥用闸门 |
| 记忆隔离 | 完全隔离 | 每人独立记忆/事实/目标/画像，互相看不见 |
| 知识库 | 默认只有主人可用 | 访客提问不引用主人文档；访客可自己发文本入库吗？→ 暂不（文件入库仅主人） |

## 二、数据模型

### 用户态表（加 user_id 列，8 张）

| 表 | 主键变化 | 说明 |
|---|---|---|
| memories | +user_id（索引 (user_id, id)） | 对话记忆，FTS 同步带 user_id |
| facts | UNIQUE → (user_id, subject, predicate, object) | 重建表迁移 |
| profile | PK → (user_id, dimension) | 重建表迁移 |
| concerns | PK → (user_id, topic) | 重建表迁移 |
| jargon_terms | PK → (user_id, term) | 重建表迁移 |
| goals / unresolved_issues / style_examples | +user_id | 简单加列 |

### 主人专属表（无 user_id，访客路径绝不触碰）

work_log、behavior_events、weekly_reports、lessons、daily_summaries、
knowledge_chunks、documents、executor_commands、novel_facts、reminders、
writing_log、mood_log、fitness_log、fitness_facts

### user_id 语义

- 主人 = `QQ_ADMIN_ID`（.env，QQ 推送同款配置）；未配置回退 `'owner'` 哨兵（测试/本地）
- 访客 = QQ 号数字串（服务端校验：1-12 位数字，非法 400 fail-closed）
- 老库迁移：8 张表 `user_id=''` 的行回填主人身份（幂等）
- 主人查询兼容回填前 `''` 行（`user_id IN (?, '')`）；访客查询严格 `=`

## 三、隔离边界（chat 路径）

- 访客注入：自己的 memories/facts/profile/concerns/jargon/style_examples/goals/unresolved
- 访客零注入：知识库（含小说/健身卡）、行为数据、情绪、lessons、主人 facts
- 访客命令门禁：worklog/reminders/documents/resume/fitness/novel/executor 跳过；
  goals（按人）、search（只搜自己）、time（通用）可用
- 访客写库：消息、facts（自动提取）、goals、术语、风格范例、unresolved——全部带自己 user_id
- 主人面板 /messages、/messages/search 只返回主人数据

## 四、访客防滥用闸门（"任何人都能聊"的对价）

| 闸门 | 数值 | 位置 |
|---|---|---|
| 滑动窗口限流 | 60s ≤ 10 条 | chat 入口（超限拒绝，不烧 LLM、不写库） |
| 日上限 | 24h ≤ 300 条/人 | 同上（内存态，重启清零可接受） |
| 追踪上限 | 最多 2000 个访客计数 | 防伪造 QQ 号撑爆内存，超出淘汰最老 |
| 消息长度 | 访客 2000 字 / 主人 8000 字 | chat 入口 |
| 记忆淘汰 | 访客记忆 30 天直接删 | evict_stale（6h 周期） |
| 主人记忆保留 | 低 importance 365 天；importance≥1 永久 | 不变 |

访客确认过的持久设定（facts）不随 30 天淘汰——facts 层永久保留。

## 五、检索隔离的实现细节

- **FTS5**：memories_fts 加 `user_id UNINDEXED` 列，查询 `WHERE MATCH ? AND user_id = ?`
  （主人 `IN (?, '')` 兼容回填前旧行）
- **向量（vec0）**：KNN 是全局近邻、无用户维度——取 k=100 后 Python 层过滤
  当前用户再截 20，避免"访客向量离得近把主人记忆挤出窗口"
- **BM25**：`_bm25_memories` / `deep_keyword_search` 全程带 user_id
- **话题热度**：`_topic_boost_map` 按 user_id 统计

## 六、定时任务隔离

- consolidation：按 user_id 分组逐人整合（facts/concerns 各归各）
- weekly_reflect / daily_summary / weekly_stats / top_topics：只统计主人
- refresh_profile：只刷新主人画像
- progress_sync：主人专属 facts（课程/项目进度）
- evict_stale：全局策略 + 访客 30 天激进淘汰
- qq_reminder_push：主人专属通道不变

## 七、插件侧（astrbot_plugin_xy v1.4.0）

- `can_chat(sender, group, owner_qq)`：群聊 False；owner 未配置 False（fail-closed）；私聊一律 True
- `should_handle(...)`：保留原白名单语义，仅用于文件入库闸门
- /api/chat 请求带 `user_id=sender`；群聊静默、访客不 stop_event（不挡其他插件）
- metadata.yaml 与 register 装饰器同步版本

## 八、运维要点

- 部署：`ssh jd` → git pull → `pkill -f 'run\.py\$'` → `setsid nohup .venv/bin/python run.py`
- 插件：复制 `qq/astrbot_plugin_xy/{main.py,metadata.yaml}` 到
  `/opt/astrbot/data/plugins/astrbot_plugin_xy/` → `systemctl restart astrbot`
- 限流是内存态：重启服务即清零（可接受，防的是刷账单不是审计）
- 迁移是幂等的：init_db 每次启动都跑，回填只碰 `user_id=''` 行
- 测试基线：`cd server && /tmp/paa-venv/bin/python -m pytest -q`（v0.4：296 passed, 1 skipped）
