# 个人智能助手 · 实施方案细则

> 定位：Windows 本地 + JD 服务器混合部署，桌面悬浮机器人形态，
> 实现"记忆 → 分析 → 学习"闭环的个人工作助手。
> 参考蓝本：Wave Memory（AstrBot 插件，yh-user999/astrbot_plugin_wave_memory），取其记忆闭环架构，弃其群聊角色扮演部分。
> 版本：v0.1（方案评审稿）

---

## 一、总体目标与最终效果

### 1.1 最终形态

你的 Windows 桌面角落有一个**悬浮机器人图标**（半透明圆形，可拖拽）。它具备：

| 能力 | 效果 |
|------|------|
| **长期记忆** | 记住你所有对话、工作内容、项目进度。三个月前说过的"RAG 向量化性能问题"，今天再提它就能接上 |
| **行为感知** | 自动知道你几点开始工作、用哪些软件、查过什么技术文档、提交了多少代码，无需手动汇报 |
| **智能分析** | 每周日晚自动生成《学习进度反思》：本周成长点、行为模式变化、下周建议 |
| **主动提醒** | "这周 RAG 调优相关的话题比上周多 3 倍，要不要我整理一份资料？" |
| **工作日志** | 你说一句"记录：下午调向量化性能"，自动归档；月底问"我 6 月干了什么"秒答 |
| **多端可达** | 电脑上悬浮球、浏览器 localhost 页面；可选接 QQ bot，手机随时用 |

### 1.2 使用场景演示（真实对话）

```
你：帮我看看这个报错
助手：[检索到 3 周前你问过类似问题，当时用降维解决] 上次我们是用 PCA 降维绕过去的，
     这次报错堆栈不一样……（给出针对性回答）

你：记录：今天下午2-5点调 RAG 召回率，从 0.62 提到 0.71
助手：已记录 ✓（自动归档为"项目：12周AI应用 / 第5周 / RAG调优"）

你：最近我是不是老在晚上写代码？
助手：是的，过去 14 天你的 git 提交集中在 22:00-01:00（占 63%），
     白天浏览器记录里文档阅读集中在上午……（附统计图）

[周日 21:00 推送]
《本周反思》：
  · 成长点：独立解决了 embedding 维度不匹配问题，比上周同类问题快 40%
  · 模式变化：提问从"怎么解决"变为"为什么这样设计"，进入深度理解阶段
  · 建议：第 6 周目标是重排序优化，建议本周补齐 3 篇 rerank 论文阅读
```

## 二、系统架构（三层）

```
┌─────────────────────────────────────────────────────────┐
│ 交互层                                                   │
│  ├─ 桌面悬浮球（PySide6）：悬浮图标/聊天气泡/托盘/通知     │
│  ├─ Web 页面（FastAPI 静态页）：仪表盘/记忆浏览/周报归档   │
│  └─ （可选）QQ bot 私聊转发                               │
├─────────────────────────────────────────────────────────┤
│ 服务层（JD 服务器，7×24 在线，FastAPI 单进程）             │
│  ├─ 聊天编排：LLM 调用（DeepSeek API）+ 工具调用          │
│  ├─ 记忆闭环：摘要整合 → facts/向量 → 检索 → 注入          │
│  ├─ 行为接收：采集事件 API + 统计聚合                      │
│  ├─ 画像服务：四维度画像，每周增量更新                     │
│  ├─ 周报服务：定时任务（周日晚）+ 推送                     │
│  └─ 存储：SQLite（主库）+ sqlite-vec（向量）               │
├─────────────────────────────────────────────────────────┤
│ 采集层（Windows 本地，Python 守护进程，开机自启）           │
│  ├─ 前台窗口监控（Win32 API，5-10s 轮询）                  │
│  ├─ 浏览器历史采集（Chrome/Edge History 增量）             │
│  ├─ git 提交扫描（项目目录定时增量）                       │
│  └─ 事件推送（批量 JSON → 服务器，断网缓存本地重试）        │
└─────────────────────────────────────────────────────────┘
        组网：Tailscale（免费，两台机器组虚拟局域网）或 frp
```

**分工原则**：
- 数据源在 Windows → **采集必须在本地**（浏览器历史、窗口信息无法远程拿）
- 大脑在服务器 → 记忆不丢、电脑关机周报照跑、以后接手机入口零改动
- 交互壳在两端 → 悬浮球负责"在身边"的感觉，Web 负责"看数据"

## 三、技术选型明细

| 层 | 组件 | 选型 | 理由 |
|----|------|------|------|
| 服务 | Web 框架 | FastAPI + uvicorn | 异步、类型友好、单进程够用 |
| 服务 | 数据库 | SQLite + sqlite-vec 扩展 | 零运维、单文件好备份；个人数据量（<50 万条）无压力 |
| 服务 | LLM | DeepSeek API（OpenAI 兼容） | 便宜（约 ¥1/百万 token 输入）、够用；预留换模型接口 |
| 服务 | 向量模型 | 智谱 BigModel `embedding-3`，2048 维 | 与当前 `.env` 生产配置一致，兼容 OpenAI Embeddings 协议 |
| 服务 | 定时任务 | APScheduler | 进程内调度，无需 cron |
| 采集 | 前台窗口 | ctypes + GetForegroundWindow/GetWindowText | 无第三方依赖，Win32 原生 |
| 采集 | 浏览器历史 | 复制 History SQLite 文件后读取（Chrome/Edge） | 避免文件锁；Chromium 系同一格式 |
| 采集 | git | subprocess 调 `git log --since` 增量 | 简单可靠，不装钩子也行 |
| 桌面 | 悬浮球 | PySide6（Qt6） | 与采集器统一 Python 栈；无边框透明窗 + 托盘 + 通知原生支持 |
| 桌面 | 打包 | PyInstaller | 打成单个 exe，双击即用 |
| 组网 | 内网穿透 | Tailscale（首选）/ frp | 免费、加密、免公网 IP |
| 部署 | 服务器 | systemd 或 docker compose | 一条命令重启，日志轮转 |

**为什么不选**：
- 不用 Chroma/Milvus 等向量库服务 → 个人数据量 sqlite-vec 足够，少一个常驻进程
- 不用 Electron → 技术栈割裂，打包 200MB+；PySide6 一个 60MB exe 搞定
- 不用 MongoDB/PostgreSQL → SQLite 单文件备份/迁移最简单，这是个人项目第一优先级

## 四、数据库设计（核心表，SQLite）

```sql
-- ① 对话记忆（情境记忆，向量化）
CREATE TABLE memories (
  id INTEGER PRIMARY KEY,
  sender TEXT,                -- 'user' / 'assistant'
  content TEXT,               -- 原文
  summary TEXT,               -- 整合后的摘要（LLM）
  topics TEXT,                -- JSON 数组，如 ["RAG","向量检索"]
  ts TEXT,                    -- ISO 时间
  importance REAL DEFAULT 1.0 -- 被引用+0.02，上限 3.0（抄 Wave Memory）
);

-- ② 事实表（永久性知识，三元组）
CREATE TABLE facts (
  id INTEGER PRIMARY KEY,
  subject TEXT, predicate TEXT, object TEXT,  -- 如 ('用户','在做','12周AI LLM应用项目')
  source_memory_id INTEGER,
  confidence REAL DEFAULT 0.7,
  updated_at TEXT
);

-- ③ 画像表（四维度，带置信度和更新时间）
CREATE TABLE profile (
  dimension TEXT PRIMARY KEY,   -- technical_background / work_habit / learning_rhythm / project_info
  value TEXT,
  confidence REAL,
  updated_at TEXT
);

-- ④ 工作日志（手动记录）
CREATE TABLE work_log (
  id INTEGER PRIMARY KEY,
  date TEXT, time_range TEXT,   -- '14:00-17:00'
  content TEXT,                 -- 做了什么事
  project TEXT,                 -- 关联项目
  tags TEXT,                    -- JSON
  created_at TEXT
);

-- ⑤ 行为事件（采集器推送的原始事件）
CREATE TABLE behavior_events (
  id INTEGER PRIMARY KEY,
  kind TEXT,                    -- app_usage / browser / git_commit / manual
  name TEXT,                    -- 应用名 / 域名 / 仓库名
  detail TEXT,                  -- 窗口标题 / 页面标题 / commit message
  start_ts TEXT, end_ts TEXT,   -- 时长事件有起止
  meta TEXT                     -- JSON 扩展
);

-- ⑥ 周报归档
CREATE TABLE weekly_reports (
  id INTEGER PRIMARY KEY,
  week TEXT,                    -- '2025-W25'
  content TEXT,                 -- 完整报告 Markdown
  stats TEXT,                   -- JSON 统计数据
  created_at TEXT
);
```

向量存储：memories 的 embedding 存 sqlite-vec 虚拟表，按 id 关联。

## 五、核心机制设计

### 5.1 记忆闭环（抄 Wave Memory 骨架，删掉群聊部分）

```
对话结束（或每 N 条消息）→ LLM 结构化整合（照抄 consolidation.py 的 prompt）：
   { summary: 一句话概括,
     topics: 最多3个名词短语,
     facts: 最多5个三元组（带主语人名）,
     relations: 主题间关联 }

→ facts 进 facts 表（去重：同 subject+predicate 则更新）
→ 对话片段 + embedding 进 memories
→ 画像增量：若 facts 涉及四个维度 → 更新 profile 表

回复前（工具调用式检索）：
   query → embedding → sqlite-vec 检索 Top-8（相似度 × importance × 时间衰减）
   + FTS5 关键词检索 Top-3（精确匹配人名/术语）
   → 注入 prompt，格式：[记忆] {日期}: {内容}
```

关键参数：min_similarity 0.35、注入上限 5 条、importance 衰减 30 天半衰期。
个人场景不需要 Wave Memory 的五阶段管线（那是万级群聊多跳联想），BM25+向量混合足够，省掉复杂度。

### 5.2 行为采集（三通道技术细节）

| 通道 | 实现 | 频率 | 数据格式 |
|------|------|------|----------|
| 前台窗口 | ctypes `GetForegroundWindow` → `GetWindowText` + 进程名 | 5-10s 轮询，窗口变化才记录 | `{kind: app_usage, name: "vscode", detail: "main.py - 12周项目", start, end}` |
| 浏览器历史 | 复制 `%LOCALAPPDATA%\Google\Chrome\User Data\Default\History` → sqlite 读 `urls`+`visits`，按 last_visit_time 增量 | 每 10 分钟 | `{kind: browser, name: "stackoverflow.com", detail: "sqlite-vec python install"}` |
| git | 定时扫描配置的项目目录 `git log --since=<上次>`（或 post-commit 钩子推送） | 每 15 分钟 / 事件触发 | `{kind: git_commit, name: "dsh-plugins", detail: "fix: memory injection race"}` |

隐私策略：浏览器事件只保留 域名+标题关键词，detail 最长 80 字符，正文不上传；设置页一键"清除全部行为数据"。

### 5.3 行为分析

- **统计维度**（纯 SQL，无 LLM）：
  - 工作时间分布（按小时/星期）、应用时长 Top10、切窗频率
  - 浏览器话题分布（域名聚合 + 标题分词归类）
  - git 提交频率/时段/项目分布
- **画像更新**（每周一次 LLM）：取本周 facts + 行为统计 → 按四维度输出更新建议 + confidence 调整
- **模式变化检测**（每周一次）：对比本周 vs 过去 4 周统计 → 输出"行为变化"清单（如"晚睡编码占比上升"）

### 5.4 每周反思（身份定义的行为规范）

触发：周日 21:00（可配置）。流程：
1. 拉本周 memories / work_log / behavior 统计
2. LLM 按固定模板生成《学习进度反思》：
   - 本周成长点（基于问题难度变化、独立解决率）
   - 行为模式变化（统计对比）
   - 项目进度核对（对照 12 周计划表）
   - 下周建议（1-3 条具体可执行）
3. 存 weekly_reports → 推送桌面通知 + Web 归档

### 5.5 桌面悬浮球（PySide6）

- 主窗口：无边框 + 透明 + 窗口置顶 + 可拖拽，默认 48px 圆形机器人图标（emoji/自制 SVG）
- 点击展开：聊天气泡面板（450×600，半透明毛玻璃效果，QGraphicsDropShadowEffect）
- 托盘菜单：打开面板 / 今日概览 / 周报 / 暂停采集 / 退出
- 通知：QSystemTrayIcon.showMessage（周报推送、主动提醒）
- 后端：QWebSocket 连服务器（或 httpx 轮询，v1 用轮询更省事）

## 六、实施步骤与验收标准

### M1：服务器记忆闭环（预计 3-4 个工作日）

| 步骤 | 内容 | 验收标准 |
|------|------|----------|
| 1.1 | FastAPI 骨架 + SQLite 建表 + sqlite-vec 接入 | `/health` 返回各服务状态 |
| 1.2 | 聊天接口：LLM 编排 + 记忆检索注入 | 对话能引用 3 天前的记忆 |
| 1.3 | 摘要整合服务（抄 consolidation prompt） | 聊 10 条后 facts 表出现正确三元组 |
| 1.4 | 画像服务 + 手动日志命令（"记录：…"） | "记录：…"后 work_log 正确归档 |
| 1.5 | Web 界面（聊天 + 记忆浏览 + 仪表盘） | 浏览器可用，记忆可搜索浏览 |

**验收**：在服务器上跑通"连续聊天 3 天 → 第 4 天提问能召回前 3 天内容"。

### M2：行为采集（预计 3-4 个工作日）

| 步骤 | 内容 | 验收标准 |
|------|------|----------|
| 2.1 | 前台窗口采集器 + 事件推送（断网缓存） | 服务器 behavior_events 出现 app_usage |
| 2.2 | 浏览器历史采集（增量） | 服务器出现 browser 事件，无锁文件报错 |
| 2.3 | git 扫描采集 | 提交记录入库，commit message 可见 |
| 2.4 | 统计聚合 API（时段/应用/话题/提交） | Web 仪表盘出图 |

**验收**：Windows 开 1 天，仪表盘能看到完整的一天行为时间线。

### M3：桌面悬浮球（预计 3-4 个工作日）

| 步骤 | 内容 | 验收标准 |
|------|------|----------|
| 3.1 | PySide6 悬浮球 + 气泡聊天窗 + 托盘 | 桌面可用，拖拽/最小化正常 |
| 3.2 | 接入服务器聊天 API + 通知 | 悬浮球对话与 Web 一致，周报弹通知 |
| 3.3 | PyInstaller 打包 exe + 开机自启（任务计划程序） | 双击即用，重启自启 |

**验收**：桌面悬浮球完成"随手聊天 + 记录工作 + 收周报"全流程。

### M4（可选）：QQ 接入（预计 2 个工作日）

服务器上现有 QQ bot（AstrBot）加一个转发插件：私聊消息 → 本地助手 API → 回复回传。
好处：手机随时可用；坏处：QQ 协议风控风险（建议小号）。

## 七、投入与成本估算

| 项 | 估算 |
|----|------|
| 开发工作量 | M1-M3 共约 10-12 个工作日（一个人） |
| 服务器资源 | JD 服务器现有配置足够（2C4G 即可），新增 SQLite + FastAPI 无压力 |
| LLM 成本 | 个人使用量（日均 50 次对话 + 采集摘要），DeepSeek API 约 **¥5-15/月** |
| Embedding 成本 | 智谱 BigModel `embedding-3`，以当前账户实际计费为准 |
| 组网 | Tailscale 免费版足够（100 台设备） |
| 一次性 | 无（全部开源组件，AGPL 只影响 Wave Memory 部分代码的再分发，个人自用无碍） |

## 八、风险与边界

| 风险 | 等级 | 应对 |
|------|------|------|
| 浏览器历史隐私 | 中 | 只采域名+标题关键词；一键清除；数据只存自己服务器 |
| QQ 协议风控（若接） | 中 | 用小号；仅私聊；不群发 |
| Windows 浏览器版本升级改库结构 | 低 | 解析失败自动降级为"仅域名"，不崩溃 |
| LLM 记忆污染 | 低 | 沿 Wave Memory 思路：noise 7 天淘汰、事实去重、画像带 confidence |
| 服务器挂机 | 低 | systemd 自动重启；本地采集器断网缓存重试 |
| 许可证 | 低 | AGPLv3 个人自用无限制；若借鉴代码进私有闭源项目需注意，建议只抄思路不抄代码 |

## 九、与 Wave Memory 的对应关系（抄哪些/弃哪些）

| Wave Memory 组件 | 处理 |
|------------------|------|
| consolidation.py 摘要 prompt | **照抄改造**（单用户版） |
| memories/facts/tag 表结构 | **照抄改造** |
| importance 衰减 + 淘汰策略 | **照抄** |
| 注入格式 `[记忆] {sender}({time}): {content}` | **照抄** |
| 五阶段检索管线（EPA/金字塔/脉冲/测地线） | **弃**（个人数据量用 BM25+向量足够） |
| 灵魂引擎（BDI/情绪/做梦/欲望） | **弃** |
| 好感度/人格进化/跨群画像 | **弃**（保留"画像"概念，重做成四维度） |
| 黑话系统 | **降级**：保留"术语词典"（你问过的技术名词自动建档） |
| WebUI 知识图谱 | **降级**：简化为记忆浏览 + 话题聚合页 |
