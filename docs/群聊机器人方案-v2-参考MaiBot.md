- **不做**：为此把本项目改为 GPL，或把仓库改为 private。

## 1. 从该项目实际代码中确认到的可借鉴点

以下为直接读取仓库确认的事实，不是推测：

1. **发言时机是独立机制，不是“有问必答”**
   `src/chat/heart_flow/` 下有会话级 heartflow 管理，
   `heartflow_manager.adjust_talk_frequency(session_id, frequency)`
   支持按会话调节发言频率。

2. **注意力/发散风格可配置为档位**
   `src/maisaka/attention_drift.py` 定义了三组正交档位，并在
   `src/config/official_configs.py` 中以枚举配置暴露：
   - `drift_level`: `subtle | active | scattered | wild`
   - `anchor_policy`: `strict | balanced | loose`
   - `reaction_style`: `reserved | natural | lively`
   这些档位以自然语言规则注入，用来控制“联想强度”“是否回到主题”
   “是否用短反应开头”。

3. **会话隔离以 `session_id` 为一等公民**
   消息处理、命令禁用、权限提示等都按 `session_id` 生效
   （`src/chat/message_receive/bot.py`）。

4. **人物身份与会话分离**
   `src/person_info/person_info.py` 用 `platform + user_id` 生成稳定
   `person_id`，并有 `is_person_known()`、`strict_known` 等“是否已认识”的
   显式判定，而不是默认认识所有人。

5. **风格目标是自然口语，而非助手腔**
   README 明确反对长篇大论与 Markdown 分点，强调“该说话时说话，
   该闭嘴时闭嘴”。

## 2. 与我们既有约束的冲突与取舍

| 该项目做法 | 我们的处境 | 结论 |
| --- | --- | --- |
| 积累对个人的长期了解、跨场景人格 | 你要求群聊不暴露管理员 | **不采纳跨场景画像**；群内不建管理员画像 |
| 群内主动发言、模仿群成员风格 | 暴露面与隐私风险 | 采纳“发言时机”，**不采纳风格模仿他人** |
| 群成员长期人物档案 | 涉及第三方隐私 | 默认不建档；仅保留当轮所需 |
| 一套人格贯穿所有场景 | 私聊已有稳定人格与记忆 | **按模式分离人格上下文** |

核心取舍：借鉴“**什么时候说、怎么说**”，不借鉴“**记住谁、认识谁**”。

## 3. 更新后的方案（v2）

保留 v1 的模式开关，新增发言时机与风格档位。

### 3.1 配置（默认全部保守）

```
ASSISTANT_MODE=personal          # personal | group
GROUP_ALLOWED_IDS=               # 空=不响应任何群
GROUP_REQUIRE_MENTION=true       # 默认仅被 @ 才回应

# 发言时机（借鉴 heartflow 思路，自行实现）
GROUP_TALK_FREQUENCY=0.0         # 0.0=只在被@时说话；>0 允许少量自主接话
GROUP_SILENCE_SECONDS=60         # 同群两次自主发言最小间隔
GROUP_MAX_REPLIES_PER_HOUR=6     # 每群每小时自主发言上限

# 表达档位（借鉴 attention_drift 思路，自行实现）
GROUP_DRIFT_LEVEL=subtle         # subtle | active
GROUP_ANCHOR_POLICY=strict       # strict | balanced
GROUP_REACTION_STYLE=reserved    # reserved | natural
```

当前已落地的 QQ 插件配置名为 `assistant_mode`、`group_allowed_ids`、
`group_require_mention`、`group_trigger_prefix`、`group_cooldown_seconds` 和
`group_max_replies_per_hour`；上面的 `GROUP_TALK_FREQUENCY` 与风格档位仍是后续设计，
尚未接入运行代码。

要点：

- `GROUP_TALK_FREQUENCY=0.0` 是默认值，保证首次开启群聊时行为可预期。
- 档位只提供保守的一半选项，不提供 `wild`/`loose`/`lively`，避免群里失控。
- 所有开关只能由服务端配置决定，群内任何人不能用自然语言改。

### 3.2 发言时机（自主判定，但有硬上限）

判定顺序：

1. 群不在白名单 → 不响应。
2. 被 @ 或命中前缀 → 一定响应。
3. 未被 @ 时，按下列条件才允许自主接话：
   - `GROUP_TALK_FREQUENCY > 0`；
   - 距上次自主发言超过 `GROUP_SILENCE_SECONDS`；
   - 未超过每小时上限；
   - 当轮消息与机器人已有能力相关（如明确提问、可核实的事实性问题）。
4. 其余情况保持沉默，并且**不解释为什么不说话**。

与该项目的差异：我们把“兴趣度”降级为**明确的可解释条件**，
不引入难以预测的情绪化主动发言。

### 3.3 表达风格（群聊专用）

- 短句优先，不用 Markdown 分点、不用标题；
- 单条回复默认不超过约 200 字；
- 不复述群消息原文，不@多人；
- 不模仿具体成员的说话风格（避免针对个人建模）；
- 不使用“主人/管理员/权限”等词。

### 3.4 身份与隐藏管理员（沿用 v1，不放松）

- 群作用域下即使发言人 QQ 号等于 `qq_admin_id`，也不赋予管理员身份；
- 群作用域永不映射到 `owner`，不读写按 `user_id` 隔离的个人表；
- 管理员专属能力在群里对所有人一致表现为“不提供”，而非“无权限”；
- 不确认也不否认任何人是否为管理员。

借鉴点：该项目的 `is_person_known()` 思路可用于我们**反向**目的——
群聊里显式声明“**不认识任何人**”，从而避免熟悉度差异泄露身份。

### 3.5 数据边界（比 v1 更明确）

- 群消息**不进入** `memories`、`facts`、`profile`、`lessons`、`goals`；
- 群聊只使用**当轮上下文**，默认不建群历史表；
- 不建群成员档案，不做跨群识别与合并；
- 群聊默认关闭主动事件调查与联网检索（延迟与信息面双重考虑）。

## 4. 预期效果（可观察）

开启 `ASSISTANT_MODE=group` 后：

1. **不会被认出管理员**：你在群里与其他成员待遇一致，无额外熟悉度，
   无个人记忆引用，无专属功能差异。
2. **不再是问答机器**：被 @ 必答；未被 @ 时默认沉默，可按频率允许少量接话，
   且有间隔与每小时上限，不会刷屏。
3. **说话更像人**：短句、口语、无 Markdown 分点，不长篇大论。
4. **风险可控**：白名单 + 默认仅 @ 触发 + 默认零自主发言 + 群聊不联网，
   首次上线的暴露面接近最小。
5. **可回退**：切回 `personal` 即恢复现状（群聊静默、私聊能力不变）。

明确不会获得的效果（避免预期错位）：

- 不会在群里记住谁是谁；
- 不会积累群成员画像或跨群关联；
- 不会模仿某个成员的语气；
- 不会像该项目那样把群聊作为“数字生命成长”的语料来源。

## 5. 验收标准（在 v1 基础上补充）

沿用 v1 第 7 节全部条目，并新增：

9. `GROUP_TALK_FREQUENCY=0` 时，未被 @ 的群消息一律无回复。
10. 自主发言受间隔与每小时上限约束，超限即沉默且不提示原因。
11. 群回复不含 Markdown 分点/标题，长度受限。
12. 群聊不触发联网检索与事件调查（trace 中相应字段为空）。
13. 档位配置非法值时回退到最保守档位，不报错也不放宽行为。
14. 群内任何自然语言请求都不能修改模式、白名单、频率与档位。

## 6. 实施顺序（更新）

1. 配置与模式解析（默认 `personal`，行为不变）。
2. 群作用域身份隔离与 fail-closed 断言。
3. 群聊提示词与统一话术（含风格档位注入）。
4. 发言时机控制（频率、间隔、每小时上限）。
5. 插件入口按模式与白名单放行群消息。
6. 验收测试：身份探测、提示注入、频率上限、风格约束、数据隔离。
7. 全量回归、脱敏检查、提交推送、部署与端到端复验。

## 7. 风险

- 自主发言一旦调高，群内噪音与误判风险明显上升，建议长期保持默认 0。
- 群聊放开后，提示注入攻击面扩大，必须有专门测试。
- 借鉴设计时若直接照搬其提示词或代码，会引入 GPL 合规问题。
