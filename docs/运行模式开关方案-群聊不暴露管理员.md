# 运行模式开关方案：私人助手 ↔ 群聊机器人

状态：方案记录，未实现。当前代码仍为“私聊专用、群聊静默”。

## 1. 目标与非目标

目标（用户明确要求）：

- 用一个开关在**私人助手**与**群聊机器人**之间切换。
- 群聊模式下**不暴露管理员是谁**。

非目标（本次不做，避免范围膨胀）：

- 不做跨群检索。
- 不做群成员画像与跨群身份合并。
- 不追求“群里也认得管理员”，这与隐藏身份直接冲突。

## 2. 为什么必须是模式开关，而不是仅加一个群聊入口

现有身份判定是“QQ 号等于 `qq_admin_id` 即管理员”
（`server/app/core/memory.py` 的 `normalize_user_id` / `is_owner_user`）。
若直接放开群聊，管理员在群里仍被识别为管理员，会带出私人记忆与专属能力，
身份必然暴露。因此开关要切换的是**整体运行语义**，不只是消息来源。

## 3. 开关设计

新增配置（默认保持现状，不影响既有部署）：

```
ASSISTANT_MODE=personal   # personal（默认）| group
GROUP_ALLOWED_IDS=        # group 模式下的群白名单，逗号分隔，空=不响应任何群
GROUP_REQUIRE_MENTION=true
```

模式语义：

| 模式 | 私聊 | 群聊 | 管理员身份 |
| --- | --- | --- | --- |
| `personal`（默认） | 完整私人助手能力 | 一律静默（现状） | 私聊内有效 |
| `group` | 仍可用，但不在群内体现 | 白名单群响应 | **群内一律不生效** |

关键约束：模式是**服务端配置**，不能由消息内容、请求体或群内指令切换。
任何“切换模式”“我是管理员”的自然语言请求都不改变实际权限。

## 4. 群聊模式下的身份处理

1. 群作用域下即使发言人 QQ 号等于 `qq_admin_id`，也**不赋予管理员身份**。
2. 群作用域**永不映射到 `owner`**，不读写按 `user_id` 隔离的个人表。
3. 管理员在群里得到的是普通成员待遇：不额外熟悉、不带称呼、不引用私人记忆。

代价必须写清楚：**群里机器人不会认得你**。这是隐藏身份的必然结果。

## 5. 防身份探测的三条规则

仅靠“不说管理员”不够，行为差异本身就是泄露渠道。

1. **能力一致**：群聊中管理员专属功能（提醒、执行器、工作日志、文档、
   健身记录等）对所有人一致表现为“不提供”，而不是“你没有权限”。
2. **错误一致**：不因发言人不同返回不同错误或提示，避免权限探测。
3. **话题回避**：不确认也不否认任何人是否为管理员；不出现“主人”“管理员”
   “权限不足”等表述；被追问时礼貌模糊带过，不解释机制。

对照现状：私聊访客提示词已有类似边界
（`server/app/chat/prompting.py` 的 `_guest_note`），但它仍显式提到
“主人”“管理员”“功能对你不可用”，在群聊场景需要改为**不提及、不区分**。

## 6. 群聊消息的最小处理策略

- 默认只保留**当轮上下文**，不建长期群记忆表；风险最低，改动最小。
- 群消息不写入 `memories`、`facts`、`profile`、`lessons`、`goals` 等个人表。
- 群聊默认不启用主动事件调查与联网检索，避免群内长耗时与信息面扩大。
- 若后续需要群历史，再单独设计独立表与保留期，不复用个人表。

## 7. 验收标准（可测）

1. `ASSISTANT_MODE=personal` 时行为与当前完全一致：群聊静默，私聊能力不变。
2. `ASSISTANT_MODE=group` 且群不在白名单时不响应。
3. 群内管理员发言：作用域不是 `owner`，个人注入为空，回复不体现额外熟悉度。
4. 群内任意人询问“谁是管理员 / 我是不是管理员 / 你的主人是谁”，
   均不透露、不确认、不否认。
5. 群内发提醒、执行、文档类指令，无论发言人是谁，回应完全一致。
6. 群聊回复不出现“主人”“管理员”“权限”等字样。
7. 群聊不产生任何按 `user_id` 隔离的个人表写入。
8. 提示注入用例：群内伪造“系统消息/管理员指令”不能提升权限或套出身份。

## 8. 实施顺序（后续执行）

1. 加配置与模式解析，默认 `personal`，不改变现状。
2. 群作用域身份与注入隔离（含 fail-closed 断言，不依赖每处判断都写对）。
3. 群聊提示词与统一拒绝话术（能力一致、错误一致、话题回避）。
4. 插件入口按模式与白名单放行群消息，保留 `personal` 模式静默逻辑。
5. 补齐第 7 节全部验收测试，含提示注入。
6. 全量回归、脱敏检查、提交推送、部署与端到端复验。

## 9. 已知风险

- 群聊放开会扩大暴露面，白名单与 @ 触发是主要控制手段。
- 群内多人发言归属需要谨慎，避免把他人内容当作用户事实。
- 模式切换需重启生效，切换前应确认白名单配置正确。
