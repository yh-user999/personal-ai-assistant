# 项目状态与方案交接

> 事实快照：2026-09-20。本文只记录已核对的项目状态、当前候选方案和未完成事项；未表示候选 Agent 已经接入生产。

## 1. 当前生产链路

```text
QQ/NapCat
  → 自建 OneBot v11 HTTP 网关
  → FastAPI /api/chat
  → OneBot action 回 NapCat
```

- QQ 入站由仓库内的 `qq/onebot_gateway` 承接；它负责 OneBot 事件解析、群直达门禁、群作用域、限流、续话和发送。
- FastAPI 是事实与权限源，负责身份、群/私聊隔离、记忆、知识库、联网检索、小说工作台、健身/提醒、LLM 编排和最终审校。
- 当前生产未接入 MaiBot、AstrBot、OpenClaw、Hermes 或 AnySearch。
- AnySearch 的定位是搜索/抓页工具候选，不是主 Agent。

## 2. 当前方案

### 已确定

1. 继续保留自建 OneBot 网关和 FastAPI 主服务，不在生产 QQ 链路叠加多个 Agent。
2. QQ 群消息必须只有一个入站/出站所有者；MaiBot 或其他框架不能与自建网关同时处理同一 NapCat 事件。
3. 群消息继续使用 QQ 访客身份；不得注入主人画像、私聊事实或其他群数据。
4. 搜索结果必须经过来源质量、正文相关性、SSRF、群限额、证据边界和失败降级检查。

### 候选方向（尚未实施）

- **QQ 社交优先**：MaiBot 作为唯一外部 QQ 社交前端，FastAPI 继续提供事实、权限、记忆、联网和领域工具。
- **Windows/桌面执行优先**：评估 OpenClaw 作为受限执行侧车，不能直接读取生产数据库或 QQ 凭据。
- **长期记忆/自学习实验**：评估 Hermes，暂不替换现有记忆和画像体系。
- **开发维护**：NarraFork 继续作为开发、排障和部署入口，不作为生产聊天 Agent。
- **检索增强**：AnySearch 可作为 MaiBot 插件、MCP/HTTP 工具或 FastAPI 检索 provider；接入后仍沿用现有来源门禁和证据契约。

## 3. 最近一次真实故障

2026-09-20 17:21 左右，群里发送：

> 你知道没钱修什么仙这本书吗

最终回复为“没有可靠来源”的固定降级话术。已核对的原因是：

1. 响应 planner 首次调用超时；
2. 系统回退到规则计划；
3. 当前规则只识别带书名号，或显式“书名是/叫/为”的作品查询；
4. 该句是无书名号的裸书名，因此没有进入小说联网检索；
5. 群聊 grounding 审校发现外部事实问题没有来源后，替换为安全降级话术。

这一次不是搜索后端冷却，也不是网页抓取重试耗尽。
