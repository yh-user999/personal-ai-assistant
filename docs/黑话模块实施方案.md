# 黑话模块实施方案（第 10 课 · 设计稿）

> 定位：让机器人学会"圈内黑话"的语境语义——不是术语定义，不是事实三元组，
> 而是"某个词/短句在我们圈子里指代什么"的隐式知识，跨会话可召回、可共享。
> 版本：v0.1（方案评审稿，未实施）
> 状态：方案已定，待一期开工

---

## 一、真实用例（立项依据）

> 用户转发了某个链接，随后说了句"还有鸡蛋"。
> 实际意思是：这个链接像老人免费领鸡蛋一样，里面有免费 API token 可以领。

期望效果：

1. 当下对话：小月自然理解"鸡蛋"指链接里的白嫖福利（现有 LLM 同窗口即可做到，不是本模块的增量）
2. **跨会话**：第二天用户只说"今天还有鸡蛋吗"，没有链接上下文，小月仍能理解是问"有没有新的免费 token 链接"
3. **共享**：访客（朋友）说"还有鸡蛋"，小月也能懂——黑话属于圈子，不按人隔离

## 二、设计原则

1. **语境语义**：黑话是"词 + 触发语境 → 含义"的映射，不是词典定义；多义词靠语境区分
2. **确定性优先**：黑话层只是提高召回确定性和共享性；就算漏了，记忆语义检索仍能召回原对话兜底
3. **低成本**：日常注入零 LLM 成本；只有显式教学或命中推断信号才烧一次后台小调用
4. **防误捕获**：候选 → 转正两级状态机，"用一次信一分"，用户纠正即时覆盖
5. **共享只读**：主人维护共享池，访客只读；访客私有黑话互相隔离

## 三、数据模型（新表 `slang_terms`）

| 字段 | 类型 | 含义 |
|---|---|---|
| id | INTEGER PK | — |
| user_id | TEXT | 创建者：主人 QQ / 访客 QQ（决定池归属） |
| term | TEXT | 黑话词/短句（"鸡蛋"） |
| meaning | TEXT | 语义解释（"指链接里的白嫖福利，如免费 API token，像老人免费领鸡蛋"） |
| context_hint | TEXT | 触发语境（"链接/转发/领福利"），多义词按语境区分用 |
| source_episode | TEXT | 首次出现的原话快照（"转发链接 + 还有鸡蛋"），召回时给 LLM 当证据 |
| scope | TEXT | `shared`（主人维护，访客只读）/ `private`（各人私有） |
| status | TEXT | `candidate`（候选）/ `confirmed`（确认） |
| use_count | INTEGER | 命中次数（转正与排序依据） |
| last_used_at | TEXT | 最近使用时间 |
| created_at / updated_at | TEXT | — |

约束：`UNIQUE(user_id, term, context_hint)`；主人条目默认 `scope=shared`，访客条目 `scope=private`。

## 四、学习路径（三条捕获通道）

### 路径① 显式教学（零 LLM，规则式）
```
"记黑话：鸡蛋 = 免费token福利" / "黑话「鸡蛋」指链接里的白嫖福利"
→ 解析 term + meaning → 直接 status=confirmed（主人 → shared）
```

### 路径② 语境推断（LLM 后台，核心通道）
```
触发信号：消息含链接（URL）+ 紧跟短句（≤15 字且非链接解释）→ 后台调 LLM：
  "用户刚发了链接并说『还有鸡蛋』，判断这是否在给链接起黑话代称；
   若是，输出 {term, meaning, context_hint}；不是输出 null"
→ 有输出 → 存 status=candidate（不动声色，不打扰用户）
→ 后续该用户在合适语境再次使用该词 → 按候选语义接话，用户不纠正 = 默认对
→ 累计使用 ≥2 次 → 转 confirmed
→ 用户纠正（"不是，鸡蛋是指XX"）→ 路径③ 直接覆盖并 confirmed
```

### 路径③ 追溯纠正（零 LLM，规则式）
```
"刚才的鸡蛋是指XX" / "不对，鸡蛋是YY的意思"
→ 匹配最近使用的/最近的候选条目 → 更新 meaning + confirmed
```

## 五、召回与注入

```text
消息进来：
① 词命中：term 出现在消息里 → 注入"提示块"（见下）
② 语义兜底：消息问"XX 是啥意思/黑话"但无词命中 → 语义检索 slang 表兜底
③ LLM 结合当前语境自行决定是否采用该语义
```

**注入块格式（提示，不是指令）**：
```
<黑话> 「鸡蛋」＝链接里的白嫖福利（出处：你曾转发链接后说"还有鸡蛋"，指免费领 token 像免费领鸡蛋）
```
关键设计：带出处 = 多义词安全。用户聊"晚上炒个鸡蛋"时，LLM 看到出处（链接福利语境）判断不适用，自然不采用——词命中 ≠ 强制套语义。

- 注入排序：confirmed 优先，use_count 次之，last_used_at 兜底
- 命中时 `use_count+1` 并刷新 `last_used_at`
- 上限：单条消息最多注入 3 条

## 六、共享规则（用户已拍板：黑话是共享的）

- 主人路径①②建立的黑话 → `shared`，所有访客只读可见
- 访客建立的黑话 → `private`，仅自己可见；与共享池撞词时 private 优先
- 访客不能改主人的条目（只读）
- 管理命令（主人）：`黑话列表` / `黑话共享：鸡蛋` / `黑话删除：鸡蛋` / `黑话私藏：鸡蛋`（共享→私藏）
- 访客贡献 → 进自己的 private；主人看到好的可手动提拔进共享（三期功能）

## 七、与现有模块的边界

| 模块 | 管什么 | 例子 |
|---|---|---|
| slang_terms（本模块） | 语境语义：词在圈子里指代什么 | "鸡蛋"＝链接里的白嫖福利 |
| jargon_terms（术语表） | 正式术语定义 | "RAG"＝检索增强生成 |
| facts（三元组） | 客观事实与设定 | 用户 在学 FastAPI |
| memories（记忆） | 原始对话流水，兜底召回 | "2026-09-01 转发链接说还有鸡蛋" |

分流规则：定义型问题（什么是 X）→ jargon；显式教学/链接+短句推断 → slang；
事实陈述 → facts（现状不变）。三者写入互不重叠。

## 八、分期路线图

| 期 | 内容 | 新增 LLM 成本 | 预估周期 |
|---|---|---|---|
| **一期** | 建表（含迁移）+ 路径①显式教学 + 路径③追溯纠正 + 词命中注入（含出处）+ 共享只读 + 管理命令 + 回归测试 | 零 | 半天 |
| **二期** | 路径②语境推断（后台候选 + 转正状态机）+ 语义兜底检索 + 排序与 use_count | 每条候选 1 次小调用（量极少） | 1-2 天 |
| **三期** | 多义词 context_hint 打磨 + 访客 private 层完善 + 淘汰策略（≥180 天未用且 candidate → 删）+ 共享池管理界面命令补全 | 低 | 1-2 天 |

一期验收后再开工二期（用户逐步确认的习惯）。

## 九、验收用例（写进回归测试）

1. 显式教学：`记黑话：鸡蛋 = 链接里的免费token福利` → 落库 confirmed/shared
2. 注入生效：模拟"今天还有鸡蛋吗"（无链接上下文）→ system prompt 含 `<黑话>「鸡蛋」` 提示块
3. 多义词安全：消息"晚上炒个鸡蛋" → 注入块带出处，测试断言 LLM 收到的是提示语义（不强制）
4. 共享隔离：访客视角注入可见主人的 shared 条目；访客 private 条目对主人不可见
5. 纠正：`不对，鸡蛋是YY的意思` → 条目更新为 confirmed/新语义
6. 转正：candidate 被使用 2 次 → confirmed（二期）
7. 推断信号：链接 + "还有鸡蛋" → 生成 candidate 且不打断正常回复（二期）
8. 管理命令：`黑话列表` / `黑话删除` 正常（一期）
9. 跨用户回归：主人/访客黑话不互相污染（v0.4 既有隔离不破坏）

## 十、风险与应对

| 风险 | 应对 |
|---|---|
| 误捕获（正常聊天被当成黑话） | candidate 状态机 + 转正门槛（≥2 次不纠正）+ 出处证据注入；说"不对"即修 |
| 共享池暴露圈内信息 | 只有主人主动/默认建立的条目进 shared；可 `黑话私藏` 随时撤回；正式术语（jargon）不共享 |
| 多义词误套 | 注入带 source_episode 出处，LLM 按语境判断；context_hint 参与词命中过滤（三期） |
| 表膨胀 | 淘汰策略：candidate ≥180 天未用删除；confirmed 低 use_count ≥365 天未用降级 |
| LLM 提炼质量差 | 候选不转正、无注入影响；显式教学通道始终可用 |
